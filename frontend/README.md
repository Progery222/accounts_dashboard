# frontend — интерфейс AccountsStats

Один файл `index.html`: разметка, стили и логика без сборщика. Открывается
как есть, ничего собирать не нужно.

## Запуск

```bash
cd "C:\Users\Mobile Farm\Documents\dashboard\frontend" && python serve.py 5174
```

Бэкенд отдельно:

```bash
cd "C:\Users\Mobile Farm\Documents\dashboard\backend" && .venv\Scripts\python.exe manage.py runserver 127.0.0.1:8000
```

Интерфейс — http://127.0.0.1:5174/, API он ищет на том же хосте, порт `8000`
(константа `API_PORT` в начале скрипта).

**Порт 5174 не случайный:** он прописан в `CORS_ALLOWED_ORIGINS` бэкенда.
С другого порта запросы пройдут только при `DEBUG=True`. Если нужен другой —
добавьте его в `CORS_EXTRA_ORIGINS` в `.env`.

Чтобы указать другой адрес API (туннель, копия базы), не трогая код:

```js
localStorage.setItem('as_api_base', 'http://127.0.0.1:8010')
```

Параметр `?demo=1` в адресе включает демо-режим: интерфейс не ходит в API
вообще и работает на встроенных данных.

## Что подключено

Читается с API: список аккаунтов, профили, владельцы, группы, страны, KPI и
дельты за 24 ч / 7 д / 30 д, карточка аккаунта с постами и аудиторией,
аналитика, статус прогона, сессии площадок, аватарки и превью постов.

Пишет в API:

| Действие | Запрос |
|---|---|
| Обновить один аккаунт | `POST /api/accounts/{id}/refresh/` |
| Обновить выбранные | `POST /api/accounts/bulk-refresh/` |
| Профиль, владелец, архив, бан | `POST /api/accounts/bulk-update/` |
| Удалить выбранные | `POST /api/accounts/bulk-delete/` |
| Полный прогон и остановка | `POST /api/accounts/refresh_all/`, `/refresh-all-stop/` |
| Запустить автообновление | `POST /api/accounts/auto-refresh-run-now/` |
| Расписание | `GET/POST /api/accounts/schedule/` |
| Тест Telegram | `POST /api/accounts/schedule/telegram-test/` |
| Добавить аккаунты | `POST /api/accounts/` на каждую строку |
| Экспорт CSV | `GET /api/accounts/export-snapshot/` |

Ошибку сервера показываем как есть — текст поля `detail` уходит в уведомление,
без придуманных формулировок.

## Отрисовка

Интерфейс собран из трёх независимых слоёв внутри `#app`:

| Слой | Что в нём | Когда пересобирается |
|---|---|---|
| `#chrome` | шапка, лента прогона, полоса ошибки API | смена темы, маршрута, состояния прогона |
| `#body` | левый рельс и текущий экран | фильтры, сортировка, страница, выделение |
| `#overlay` | модалки, меню, панель массовых действий, уведомления | клики внутри окон, меню, тосты |

Раньше любое действие пересобирало весь `#app` — переключил тумблер в модалке,
и заново собирались шапка, рельс и таблица на 25 строк. Это и было моргание.

Правило: действие трогает только свой слой. Списки `OVERLAY_ACTS` и `MAIN_ACTS`
рядом с обработчиком кликов определяют, что чему соответствует; всё
неперечисленное делает полную перерисовку.

Отдельно: прогресс прогона обновляется точечно (`paintRun`), а не перерисовкой,
и анимация появления окна не проигрывается заново при кликах внутри уже
открытого окна.

Асинхронная догрузка тоже обязана попадать в свой слой. `loadSchedule()`
приезжает в открытую модалку и зовёт `paintOverlay()`: полная перерисовка
ради него пересобирала таблицу под затемнением — то же моргание, просто
отложенное на время запроса.

Замерять так (в консоли страницы): обернуть `render`, `paintBody` и
`paintOverlay` счётчиками и посмотреть, что даёт действие. Открытие центра
обновления — 0 полных перерисовок, 0 пересборок таблицы, 2 слоя оверлея.
Простой — 0 всего.

## Кнопка «Обновление»

Открывает окно центра обновления, а не запускает сбор. Внутри две вкладки:

- **Расписание** — настройки автообновления, тянутся с сервера и правятся
  на месте. Открывается по умолчанию, когда прогон не идёт.
- **Прогон** — ход текущего сбора. Открывается сразу, если прогон уже идёт.
  Кнопка «Запустить прогон» живёт здесь.

Так один клик по кнопке не начинает обход площадок.

## Подтверждения

Перед необратимым спрашиваем: удаление, бан, архив и **запуск полного
прогона**. Последнее — не формальность: прогон идёт по площадкам вашими
живыми сессиями из `backend/.env`, это настоящий трафик, а не тестовый запрос.

## Эфир TV

Три сцены по кругу, все на живых данных:

- **Сеть** — итоги по всей сети крупными цифрами, без графиков: экран на стене
  читают с нескольких метров.
- **Площадки** — сравнение подписчиков по площадкам. Одна мера на график
  (длина столбца), остальное текстом рядом: прирост за сутки и число аккаунтов.
- **Лидеры** — топ по приросту подписчиков за сутки. Если выросли меньше трёх
  аккаунтов, сцена переключается на «крупнейшие» и честно об этом пишет.
- **Динамика** — просмотры сети за 24 часа из `auto-refresh-series`. Появляется
  в ротации **автоматически, когда наберётся хотя бы 6 замеров**. Сейчас их
  меньше, поэтому сцены нет: рисовать кривую по двум точкам — врать о форме.

Сцены «Пульс» больше нет — её почасовая кривая была нарисована, а не измерена.

### Цвета площадок

Два набора (для светлых и тёмных тем) прогнаны через валидатор палитр:
полоса светлоты, порог цветности, различимость соседних пар при трёх видах
дальтонизма и контраст к фону — все проверки проходят. Порядок фиксированный,
цвет закреплён за площадкой и не переезжает при фильтрах. Плюс у каждой строки
есть значок и подпись, так что различить их можно и без цвета.

## Мелочи, на которые легко наступить снова

- **Аватарки.** Часть аккаунтов отдаёт 404 — тогда вместо картинки
  подставляются инициалы. Делает это один слушатель `error` на документе,
  на перехвате: событие `error` у `<img>` не всплывает, а inline-атрибут
  `onerror` тут не годится — подстановка через `JSON.stringify` приносит
  двойные кавычки и обрывает сам атрибут.
- **Опрос статуса.** Интервал заводится один раз и хранится в `pollTimer`.
  `bootLive()` зовётся ещё и по кнопке «Повторить» после ошибки API —
  без `clearInterval` каждая такая попытка добавляла ещё один опрос
  навсегда.
- **Знак дельты** ставит `signed()`, а не приклеенный `'+'`: иначе падение
  печатается как «+−1».
- **Список карточками или строками** решает `effView()`: уже 760 px и есть
  список всегда карточками, независимо от переключателя.

## Чего пока нет

- **Экран «Алерты»** (в настройках) — надстройка интерфейса, эндпоинта под неё
  в API нет. Список и правила там показаны как макет.
- **График «подписчики за 30 дней»** на карточке аккаунта — API не отдаёт
  историю по дням, нужен отдельный эндпоинт поверх `AccountSnapshot`.
- **Почасовая кривая в сцене «Пульс»** экрана «Эфир» — модельная, помечена
  плашкой прямо на экране.
- **Вход и импорт cookies** в настройках — кнопки на месте, запросы
  (`/api/settings/{platform}/start-auth`, `/import-cookies`) не подключены.
